# 제품이력 도우미 후속 실행 로드맵

5일차에 회사가 선택하고 조정할 제안안이다. 30·60·90일은 시작일 합의 후 적용할 기간이며 개발 납기나 검증 완료 약속이 아니다. 앞 단계의 증거가 부족하면 다음 기능을 늘리기 전에 해당 과제를 먼저 보완한다. 5일차에는 우선순위와 검증 조건을 정한다.

## 우선순위를 정하는 질문

“누구의 어떤 업무 판단을 개선하는가”, “틀리면 어떤 문제가 생기는가”, “자료와 담당자를 지금 확보할 수 있는가”, “성공을 무엇으로 확인할 것인가”에 답한다. 효과와 위험이 크고 검증 준비가 된 과제를 먼저 선택한다. 준비되지 않은 고위험 과제는 담당과 선행 조건부터 정한다. RAG·메모리·MCP 등은 이 질문을 통과한 업무 요구의 구현 후보로 검토한다.

## 단계별 진행과 다음 단계 조건

| 제안 기간 | 할 일과 책임 역할 | 남길 증거와 다음 단계 조건 |
| --- | --- | --- |
| 첫 1주 | 현업 책임자가 우선 업무 1개와 대표 질문을 고른다. 데이터 담당은 원천·필드·정답을 확인하고, 교육생은 시도·미해결 목록을 정리한다. IT는 사용할 기존 경로를 확인한다. | 문제 한 문장, 동일 버전·자료 기준, 담당자와 첫 점검일. 대표 질문의 기대값과 현재 가능한 범위가 합의되어야 다음 시험을 한다. |
| 30일 이내 | 교육생과 IT가 기존 앱의 조회·연결·배포 재현성을 확보한다. 현업·데이터 담당은 정상 10건 이상과 합의한 예외의 정답·판정을 검수한다. | 원천·실제값·완료 상태가 있는 시험표, 동료 재현 기록, 남은 오류의 담당. 기준 미달이면 수정·재시험하고 제한된 업무 시험 진입을 보류한다. |
| 31~60일 | 현업 책임자가 소수의 승인된 사용자를 정하고 IT가 계정·자료 접근·오류 접수·중지와 복구 경로를 준비한다. 같은 질문을 수작업과 도우미로 비교한다. | 정확·확인 불가·오답·실행 실패 건수, 같은 범위의 처리 시간과 사용량·비용 근거, 사용자 피드백. 중대한 오답·권한 노출 시 시험을 중지하고 원인을 확인한다. |
| 61~90일 | 현업·데이터·IT 책임자가 앞선 시험을 검토해 유지·보완·확대 중 하나를 결정한다. 자료 갱신이나 A/S 등 선택한 요구 하나를 작은 범위로 검증한다. | 효과·위험·지원 부담 비교와 책임자의 결정 기록. 선택 기능의 정확성·갱신·권한·장애·비용 인수 증거가 있어야 사용 범위를 늘린다. |

회사 자원이 부족하면 범위를 줄이거나 일정을 다시 합의한다. 외부 컨설팅의 추가 지원 시간도 별도 합의 사항이다. 화면이 완성되었다는 이유로 현업 시험과 운영 인수를 생략하지 않는다.

## 미완료 요구를 실행 가능한 과제로 바꾸기

| 요구 | 다음에 할 작은 확인 | 완료를 판단할 증거 |
| --- | --- | --- |
| 자료 정기 갱신 | 승인된 가상 자료 한 건을 바꾸고 원본·조회본·답변의 버전과 반영 시점을 확인 | 변경 전후 동일 질문, 출처·버전·반영 기록. 링크 등록만으로 자동 갱신 판정 금지 |
| 직원 로그인과 개인 대화 | 사용자 A/B의 로그인·로그아웃과 대화·자료 접근을 각각 확인 | 성공·실패·권한 분리 시험. 로그인 화면·contextId만으로 완료 판정 금지 |
| Firebase 저장 | 연결된 DB 종류와 대상 경로를 확인하고 승인된 더미 값 읽기·쓰기를 시험 | 실제 저장·재조회·접근 제한 결과. 연결 버튼 성공과 별도 판정 |
| 배포 재현성 | 기존 검증 범위의 문구 한 개를 바꾸고 새 배포본과 실제 Agent 응답을 확인 | 빌드·리비전·새 문구·완료 응답. 화면 전용 경로의 범위를 넘으면 기준 원본부터 검토 |
| A/S·모바일 | 가장 빈번한 한 업무의 필수 입력·담당·현재 자료 유무를 확인 | 현업 승인 사례와 기대 결과. 자료·권한 확보 후 별도 실험 |

## 회사와 참여자에게 필요한 노력

현업 책임자는 우선순위, 이용 범위와 주간 검토 시간을 정한다. 데이터 책임자는 원천 제공과 필드 의미·정답 검수·변경 통보를 맡는다. IT 담당은 실제 실행 환경·접근·배포·중지·복구를 맡는다. 교육생은 주간 실험 한 가지를 수행하고 기대와 실제, 실패 증거를 남겨 동료 검수를 받는다. 컨설턴트는 과제의 범위를 좁히고 검증 설계와 막힌 원인 후보를 검토한다.

권장 검토 주기는 주 1회 20~30분이다. 회사와 합의한 일정으로 확정한다. 매번 새 기능 목록을 늘리기보다 직전 약속의 증거와 다음 한 가지 실험을 확인한다.

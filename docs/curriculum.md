# 셀바스헬스케어 AI 훈련코치 · 5일 과정 커리큘럼

**2026-10-14 개정 · 기업용 제품 이력 에이전트 · Agent Designer 중심 · 외부 코칭 5일 × 4시간 = 20시간**

## 1. 개정 방향과 과정 설명

Workspace Studio를 사용하지 않는다. 오늘 실제 사용한 **Google Cloud의 Gemini Enterprise Agent Platform → Agent Studio → Agent Designer**를 기본 제작 환경으로 삼는다. ERP 제품 이력과 SW 변경통보 자료를 대조해 답하는 에이전트를 만들고, 정확성·근거·예외·세션·배포 상태를 검증한다. Google Chat은 필수 입력창에서 제외하고 필요할 때 별도로 연동하는 선택 경로로 둔다.

이름이 비슷한 제품을 구분한다. Cloud Agent Designer의 Preview는 제작자 시험 화면이며 Deploy는 실행 환경 배포다. 직원용 웹 UI나 공유 URL이 자동으로 완성되는 것은 아니다. Gemini Enterprise Business의 Agent Designer는 별도 서비스이며 그 서비스의 웹 채팅·공유 기능을 사용한다. 회사가 해당 서비스를 이용한다면 구독·앱 주소·사용자 권한을 확인한 뒤 이용 경로를 정한다. Google Workspace Enterprise 구독만으로 에이전트 서비스 이용 가능을 확정하지 않는다.

학습자는 **현업 질문 → 필요한 원천 정의 → 작은 실험 → 응답과 원천 대조 → 지침 수정 → 새 질문 재시험**을 반복한다. 화면 조작과 업무 규칙 설계를 기본으로 하며, 실시간 조회 도구·사용자 인증·서비스 운영은 준비된 환경을 사용하거나 기술 담당자와 연결한다.

## 2. 작업 범위와 준비

| 범위 | 수행 내용 | 완료 증거 |
| --- | --- | --- |
| 필수 | 문제정의, 식별자 보존, ERP·SW 데이터 사전, Agent 지침·저장·Preview, 정상·예외 검증, 미등록 티켓 초안 | 설정, 질문·실제 응답, 원천행 대조, 수정 전후 기록 |
| 준비된 환경에서 검증 | 정확 조회 도구 연결, 제한된 사용자 공유·배포 버전 시험 | 도구 호출 인수·반환값, 사용자별 실제 접속·응답 |
| 별도 후속 | ERP/Drive 주기 갱신, 실시간 Sheets 조회, 실제 A/S·모바일 입력, 전사 사용자 UI, 중앙 대화 이력·권한 관리, 티켓 자동 저장 | 담당자·필요 권한·시험 계획. 미구현을 완료로 기록하지 않음 |

수업 전 강사와 기업 IT 담당자는 Cloud 프로젝트, 사용 계정, 에이전트 제작 권한, 실행 주체의 자료 접근권한, 모델 한도·비용, 데이터 활용 범위를 확인한다. 학습자가 무작정 권한을 일괄 부여하도록 안내하지 않는다. 회사 환경이 준비되지 않으면 승인된 시연 환경과 가상 자료로 실습하고 본인 실행 여부를 기록한다.

회사 실습 자료와 공개 배포 자료를 구분한다. 공개 GitHub에는 가상 CSV와 일반 절차만 둔다. 제공 ERP·SW 원본, 전체 스냅샷, 개인 프로젝트 주소와 계정 화면은 내부 자료로 유지한다. 실제 회사 공유 범위는 변경하지 않는다.

## 3. 학습목표와 운영

1. 개별 장비 조회와 모델·버전별 집계 질문을 구분하고 필요한 키를 정한다.
2. Main/AP/프로그램 버전, 출고일/제출일/적용일을 구분하고 누락을 추정으로 채우지 않는다.
3. Agent Designer에서 역할·조회 규칙·참조자료·응답 형식을 설정하고 저장한다.
4. Preview의 새 세션과 후속 질문을 나누어 시험하고 근거 행을 직접 대조한다.
5. 정적 스냅샷, 도구를 통한 조회, 자동 갱신, 배포, 사용자 UI의 완료 상태를 설명한다.
6. 오류와 비용·한도를 기록하고 동료가 재현할 수 있는 인수인계 자료를 만든다.

대상은 기존 계획의 실무자 5명이며 실제 참석은 별도 기록한다. 조작·원천 검수·질문·기록·동료 검증 역할을 교대한다. 각 교시 순수 활동 60분, 하루 240분이다. 휴식 10분 × 3회는 별도다. 사내 보안·윤리 2시간과 최종평가 2시간은 기존 24시간 계획에서 별도로 유지한다. 4일차 실제 기록일은 2026-10-21이며 다음 교육은 2026-10-22로 안내했다. 다른 일차의 실시일·제출 마감과 개인별 참석은 별도 기록한다.

## 5. 필수 질문과 완료 기준

| 질문 유형 | 기대 행동 |
| --- | --- |
| 모델 + 전체 S/N의 펌웨어·출고일 | 정확한 동일 장비의 필드·근거 행을 제시 |
| BC380 1012 등 짧은 번호 | 다른 행·유사 번호를 선택하지 않고 전체 S/N 요청 |
| 모델 + AP 버전 최초 출고 | 해당 모델·전체 버전 조건의 ERP 출고일을 확인. SW 제출일로 대체 금지 |
| 신규 펌웨어 생산 미적용 | 목표 버전·적용 대상·승인/시행일·생산 이력 없으면 확정 불가 |
| 최초 출고 버전과 서비스 최종 버전 | 실제 이벤트 이력 필요. ERP 현재 칸·SW 최신 공지로 대체 금지 |
| 수리했는데 출고 없음·공백 의심 | 사용자 설명과 확인된 원천을 분리. 공백이 원인인지 실제 키 대조 |

정상 10건 이상과 합의한 모든 예외 유형을 시험한다. 최종 버전의 입력·기대값·실제값·원천·판정·세션을 기록한다. 데이터 정답, 적절한 확인 불가, 실행 오류, 미실행은 각각 집계한다. 회사 운영 가능 판정은 학습 완료와 별개다. 기존 공식 평가에 Chat·Apps Script·티켓 등록이 명시된 경우 Agent Designer 결과물의 대체 인정 여부를 PM·기업 담당자가 확인하며 임의 변경하지 않는다.

수작업과 에이전트의 같은 질문·자료·범위를 비교한다. 성공 건 중앙값과 실패 건수를 따로 보고하며 미측정을 성과로 쓰지 않는다. 비용 최소화는 실제 호출·토큰·요금 근거로 평가한다. 전체 데이터를 지침에 넣은 오늘 데모는 정확 조회·비용 최적화의 운영 완성형이 아니다.

## 6. 현업 요구와 후속 과제

오늘 회의의 ERP 정기 추출·Drive 동기화, 변경통보 발생 시 갱신, 직원별 채팅, 중앙 이력 관리, A/S 이력, 모바일 입력을 후속 요구로 유지한다. 각 항목에 자료 책임자·접근 범위·갱신 방식·실제 시험을 배정한다. 작성 중인 회사 내규와 캘린더 접근권한은 별도 요구로 남기며 이번 20시간의 완료 범위를 임의 확대하지 않는다.

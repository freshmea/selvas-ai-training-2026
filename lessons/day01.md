# 1일차 PBL 진행 가이드 · Agent Designer

**2026-10-14 개정 · 4시간 · 기존 데이터 실습과 오늘 에이전트 검증을 연결**

[기록지](../worksheets/day01-pbl.md) · [5일 커리큘럼](../docs/curriculum.md)

## 목적과 완료 수준

제품 이력 문의를 정의하고 필요한 원천을 찾아 Agent Designer의 첫 응답을 검증한다. Workspace Studio의 메시지 시작·답장 단계는 사용하지 않는다. Cloud Agent Designer에서 지침·자료·Preview를 구성하고, 실제 원천값과 응답을 대조한다. Google Chat은 이번 기본 실습에 필요하지 않다.

1일차 완료물은 문제정의, 데이터 규칙, 에이전트 지침, 정상·예외 시험 기록이다. 정적 자료 응답을 실시간 Sheets 조회라고 쓰지 않는다. 계정이 막힌 사람은 지침·정답표·수동 대조를 수행하고 본인 Preview는 미실행으로 기록한다. 강사 시연 관찰과 본인 실행을 구분한다.

## 준비

- 가상 [기본 CSV](../samples/products.csv)와 [정제 CSV](../samples/products-cleaning.csv), 개인 사본, PBL 기록지를 준비한다.
- Cloud 프로젝트·계정·제작 권한·자료 접근·모델 한도는 강사가 사전 확인한다. 실제 회사 원본은 보존한다.
- 기본 실습은 가상 24행의 작은 부분집합으로 한다. 강사 시연에서 제공 ERP·SW 자료를 사용할 때는 승인된 내부 환경과 원천행 대조표를 사용한다.
- 조작자·관찰자·기록자·질문자·검수자를 교대한다. 설명은 3~5분씩 하고 학습자 화면으로 돌아간다.
- 오늘 실제 만든 Cloud Agent Designer와 Gemini Enterprise Business의 동명 도구를 구분한다. 회사별 접속 URL은 강사가 지정한다.

## 1교시 · 질문과 원천부터 확인

첫 질문은 “000123의 모델과 Main 버전은?”이다. 기본 가상 CSV에서 스스로 찾아 소요시간과 파일·탭·S/N·셀을 기록한다. 강사용 기대값은 CSV 6행의 모델 `연습모델-A`, Main `1.2.0`이다. 원천을 확인하기 전에 답을 보여주지 않는다.

ERP의 장비 정보와 SW 변경통보의 모델·버전 문서는 관계가 다르다. 개별 장비는 전체 S/N으로 식별한다. 모델·버전별 최초 출고는 그 조건의 ERP 출고일이 필요하다. SW의 제출일만으로 출고일을 답할 수 없다. 실제 A/S 수리·업데이트 이력은 이번 두 자료에 없다.

문제정의: “누가 / 어떤 문의에서 / 어떤 자료를 찾느라 / 어떤 지연이나 오류가 생기고 / 어떤 시험으로 개선을 확인할까?” 학습자는 포함 범위와 추가로 필요한 자료도 적는다.

## 2교시 · 검색 실패와 중복 실험

1. CSV 가져오기에서 자동 숫자 변환을 확인하고 `000123`을 텍스트로 보존한다. 이미 잃은 0은 서식만 바꿔 복구하지 않는다.
2. Sheets의 전체 일치 검색으로 `000123`과 `123`을 비교한다. 같은 조건에서 첫 입력은 검색되고 둘째는 검색되지 않는지 직접 기록한다.
3. 별도 `PBL_중복실험` 탭에 A2=`앞뒤 공백을 넣은 DEMO-0006`, A3=`DEMO-0006`을 입력한다. B2/B3에 `=TRIM(A2)`/`=TRIM(A3)`, C2/C3에 `=COUNTIF($B$2:$B$3,B2)`/`=COUNTIF($B$2:$B$3,B3)`을 넣는다.
4. A3을 `DEMO-0007`로 바꾸었다가 복원해 일치건수 2→1→2를 관찰한다. 가상 실험이며 실제 키를 변경해 중복을 숨기는 방법이 아니다.
5. TRIM은 모든 특수 공백을 처리하지 않으며 COUNTIF는 대소문자를 구분하지 않는다. 정제 후 같은 키라도 다른 필드가 충돌하면 보류한다. 빈칸과 보증기간 0도 구분한다.

정상 2건·예외 2건의 정답을 먼저 작성한다. 다음 교시에서 AI가 맞았는지 이 표로 판단한다. 파일·탭·키·필드를 함께 적고 정렬로 달라질 수 있는 행번호만 남기지 않는다.

## 3교시 · Agent Designer 첫 실습

1. 승인된 Google Cloud 프로젝트에서 Agent Studio의 Agent Designer를 연다. 오늘 사용한 화면 경로를 기준으로 하며 계정의 메뉴 차이를 기록한다.
2. 이름은 `제품 이력 조회 실습_팀명`, 설명은 `가상 자료에 근거해 제품 이력을 안내하는 교육용 에이전트`로 작성한다.
3. [교육용 기본 지침](../samples/agent-instructions.txt)을 복사하고 조회 필드·자료 버전·답변 형식을 설명한다. 실제 값은 참조자료에서만 읽도록 정한다.
4. **Save**로 저장한다. 작은 가상 원천을 지침의 참조자료 구역에 넣거나, 계정에서 지원하는 Knowledge의 텍스트/PDF 파일을 등록한다. 화면에서 실제 수행한 방식을 기록한다. URL만 넣고 API 연결이라고 설명하지 않는다.
5. **Preview**에서 정상 질문을 보낸다. `000123의 모델과 Main 버전은?`, `DEMO-0004의 출고일은?`을 시험하고 원천과 대조한다. 뒤 질문의 가상 기대값은 CSV 5행 출고일 `2026-01-25`다.
6. 읽지 못한 자료는 접근 실패로 표시한다. 저장·첫 응답·정답 일치를 각각 확인한다. 정적 자료 갱신은 재등록 또는 지침 수정 후 재시험이 필요하다.

## 4교시 · 새 세션과 오류 검증

오늘 화면의 Preview 오른쪽 위 `＋ 새로운 세션`으로 독립 시험을 시작했다. 같은 세션에서는 “그 제품 출고일은?”을 이어 묻고, 새 세션에서는 장비가 특정되지 않을 때 확인 질문을 하는지 본다. 이 버튼만으로 직원별 인증·중앙 이력 보관·타인 대화 접근통제가 구현되는 것은 아니다.

| 시험 | 기대 행동 | 강사가 확인할 근거 |
| --- | --- | --- |
| 전체 S/N 정상 조회 | 동일 장비의 실제 필드 반환 | 답변과 원천 키·값·행 |
| 짧은 S/N | 전체 번호 요청, 다른 장비 추정 금지 | 후보·행번호를 임의 제시하지 않음 |
| 모델·버전 최초 출고 | 개별 S/N 강요 없이 ERP 범위·조건 확인 | SW 제출일을 출고일로 쓰지 않음 |
| 신규 펌웨어 미적용 | 적용 대상·목표·시행일 없으면 확정 불가 | 최대 버전·빈칸만으로 판정하지 않음 |
| 서비스 최종 버전 | 서비스 이력 부재 표시 | SW 공지를 장비 업데이트 증거로 쓰지 않음 |
| 429 또는 권한 실패 | 실행 오류 기록, 결과 미확인 | 재시도 시점·담당·최종 버전 재시험 |

가상 기본 CSV에서는 `000123`이 완전한 식별자다. 제공자료 데모에서 숫자 `1012` 등은 축약 번호다. 두 자료의 번호 형식 규칙을 혼용하지 않는다.

학습자는 오류 1건을 선정해 가설·지침 수정·새 세션 재시험을 기록한다. 정상 예시를 통과했다고 전체 통과로 쓰지 않는다. 오늘 최종 지침은 429로 전체 재검증하지 못했다. 배포 화면은 시연하되 **설정 저장 / Preview 응답 / Deployed / 배포 응답 / 직원 UI 접속**을 별도 단계로 적는다.

## 종료와 평가

문제·필요 자료·지침·원천·오류·다음 행동을 동료에게 설명한다. 독립 수행 / 힌트 후 수행 / 보충 필요로 기록한다. 평가 대상은 클릭 속도가 아니라 근거와 수정 판단이다. 개인별 정상·예외 시험 및 지침 버전을 제출한다.

내일 과제는 ERP·SW의 연결 키, 날짜 의미, 모델·버전별 집계 정답표다. 회사 자료 자동 갱신·A/S·모바일 입력·직원 UI는 담당자와 별도 준비 상태를 확인한다.

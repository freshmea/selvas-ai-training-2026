# 3일차 보충 실습 · 텍스트 앱 공유와 배포 실패 진단

**2026-10-21 추가 · 배포 재현성 · 비개발자용 Google AI Agent 요청 실습**

[상세 교안](../docs/deployment/text-sharing-build-failures.md) · [복사할 수정 요청문](../prompts/fix-npm-install.md) · [실습 기록지](../worksheets/day03-deployment-checklist.md) · [lockfile 참고 자료](../examples/deployment-lock/README.md)

**새 앱을 만들 때에는 [기능 중심 초기 프롬프트](../prompts/product-history-from-scratch.md)부터 시작합니다.** 전체 코드를 붙여 복원하는 대신 데이터·조회 규칙·문맥·실제 Agent 연결 요구를 전달합니다. 코드 참고는 A2A 요청 JSON 하나로 제한하고, 이후 실제 실패한 기능만 짧은 후속 프롬프트로 수정합니다.

[Notion 3일차 전체 교안](https://app.notion.com/p/3ff123060ee781c28259cc1aa9cd63cc)에는 응답 속도·자료 갱신·세션·Chat 계정 제약·기술 비교가 있습니다. Notion은 별도 접근 권한이 필요할 수 있습니다. 이 문서는 그 수업에 덧붙이는 **배포 재현성 모듈**이며 기존 4시간 운영안을 새로 실시했다는 기록이 아닙니다.

## 먼저 기억할 점

**텍스트로 소스를 공유했다고 반드시 오류가 나는 것은 아닙니다. 다만 코드 내용만 복사하면 파일 구조·의존성 버전·배포 환경까지 같아지는 것은 아닙니다.**

이번에는 `npm install` 단계에서 `Cannot read properties of null (reading 'edgesOut')` 오류가 발생한 로그를 다룹니다. 제공된 전체코드 텍스트에는 22개 파일이 있었지만 lockfile과 Dockerfile은 없었습니다. 이것은 위험 요소를 확인한 것이며, 텍스트 전달 자체가 npm 오류의 단일 원인임을 입증한 것은 아닙니다.

## 학습 목표

1. `npm install` 실패와 앱 빌드·서버 실행·Agent 호출 실패를 구분한다.
2. 텍스트를 앱으로 복원할 때 경로·파일 목록·package.json·lockfile을 함께 확인한다.
3. 시스템 설정을 직접 고칠 수 없는 환경에서 AI에게 수정·검증·미완료 보고를 요청한다.
4. Preview, 로컬 빌드, Cloud Build, 서비스 URL 응답을 별도로 기록한다.

## 45~60분 보충 활동

| 단계 | 활동 | 산출물 |
| --- | --- | --- |
| 1 | 오류 로그에서 마지막 성공 단계와 첫 실패 단계 표시 | 실패 단계 한 문장 |
| 2 | 전달 텍스트의 파일 목록과 실제 프로젝트 파일 대조 | 누락·차이 표 |
| 3 | 상세 교안의 설명을 읽고 수정 요청문을 자기 앱의 Google AI Agent에 전달 | AI 변경 파일·실행 로그 |
| 4 | 실제 배포 입력의 lockfile 포함 여부와 새 빌드 결과 확인 | 기록지와 동료 검수 |

AI가 수정할 수 없는 시스템 영역은 해결되지 않은 항목으로 남긴다. 단지 '수정 완료'라고 답했다는 이유로 배포 성공으로 판정하지 않는다.

## 제출 기준

- 정상 기준: 설치·프런트 빌드·서버 기동·Cloud Build·URL 응답의 결과와 근거를 각각 기록.
- 제한 기준: 실행 도구나 권한이 없으면 분석·프롬프트 작성까지 완료하고 실제 실행은 미실행으로 표시.
- 공유 기준: 실제 전체코드 텍스트, `.env.local`, API 키, 고객 자료는 공개 저장소에 올리지 않음. 기록지는 가상 정보로 작성.

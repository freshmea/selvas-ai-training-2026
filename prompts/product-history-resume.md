# 제품이력 조회 도우미 · 저장된 기본형에서 이어가기

대상: Google Cloud Agent Studio 앱 빌더. 2026-10-21 재개 요청.

새 앱이나 전체 소스 ZIP 대신, ERP 20행·SW 10행이 저장된 프롬프트 기본형에서 실행한다. 기존 정상 배포 앱과 Agent는 유지한다. 아래 요구를 단계별로 적용하고 실제 확인 결과를 기록한다.

## 1. 정확 조회와 장비 문맥

```text
현재 저장된 UI와 ERP 20행·SW 10행은 유지하고, 지난번 한도 오류로 적용되지 않은 조회 규칙과 대화 이어가기만 완성해 주세요. 기존 코드나 ZIP을 가져오지 말고 앱 빌더 기본 환경에서 수정하세요.
S/N은 앞뒤 공백 제거 후 전체값 정확 일치. BC380과 BC380PRO는 모델명 전체값으로 구분. S/N으로 찾은 ERP 장비의 모델과 정확히 같은 SW 이력만 연결하고 등록일 내림차순·원본 행번호·문서번호를 표시하세요. 모델만 입력하면 해당 모델 자료를 보여주되 장비 한 개를 임의 선택하지 마세요.
현재 선택 장비를 기억하여 "그 장비 제조일은?"에 같은 ERP 행의 제조일을 보여 주세요. 다른 S/N 또는 새 대화에서는 이전 장비 상태와 대화 기록을 초기화하세요. 공란은 자료 없음으로 유지하고 최신 SW 등록을 장비 적용 완료로 단정하지 마세요.
아직 외부 AI 호출은 추가하지 않습니다. 로컬 조회 근거와 대화 기록까지만 검증합니다. package.json·lockfile·Dockerfile·추가 패키지를 변경하지 마세요. 생성 후 실제 변경과 확인하지 못한 항목을 구분해 주세요.
```

단계 1이 완료되면 ERP #1과 같은 모델 SW 근거, 후속 제조일, PRO 분리, 버전 공란, 새 대화를 먼저 확인한다. 이후 실제 Agent 연결은 [초기 프롬프트의 최소 A2A 규약](product-history-from-scratch.md)을 사용한다. 생성 모델의 응답과 실제 앱의 동작은 별도로 판정한다.

## 2. 실제 Agent 연결 요구문

아래는 단계 1 검증 뒤 적용할 요청문이다. `${BRIDGE_BASE_URL}`은 해당 교육생의 실제 Agent를 호출하도록 확인한 서버 주소로 바꾼다. 단계 1 생성 중에는 동시에 제출하지 않는다.

```text
기존 화면·더미 자료·정확 조회·장비 문맥을 유지하고 실제 Agent 답변을 연결해 주세요.
연결 서버는 ${BRIDGE_BASE_URL}이며 서버가 인증합니다. 브라우저에 API 키·토큰을 넣지 마세요.
GET /api/agent/v1/card에서 name/protocolVersion/skills를 확인할 때만 연결됨을 표시하세요.
POST /api/agent/v1/message:send에 아래 최소 규약을 사용하세요.
{
  "message": {
    "messageId": "요청마다 새 UUID",
    "role": "ROLE_USER",
    "content": [{"text": "질문, 선택 범위, 선별한 ERP/SW 원본 행과 필드"}]
  },
  "configuration": {"blocking": true}
}
응답은 raw/task/result 래퍼를 확인하고 status.state 또는 status 문자열을 판독하세요.
완료 상태에서 artifacts의 parts/content 안 text를 답변으로 쓰고, 없으면 Agent 역할의 history/message에서만 찾으세요.
사용자가 보낸 근거를 AI 답으로 복사하거나 Gemini 직접 호출로 대체하지 마세요.
진행 중이며 작업 ID가 있는 경우에만 GET /api/agent/v1/tasks/{id}를 2초부터 간격을 늘려 조회하고 총 60초에 종료하세요.
HTTP 오류, 내부 error, 실패 상태, 429, 시간 초과는 오류로 표시하고 성공으로 처리하지 마세요.
같은 장비의 후속 요청은 응답 contextId를 message.contextId로 전달합니다.
다른 S/N이나 새 대화에서는 이전 Agent contextId를 초기화하세요.
질문 문장 속 전체 S/N을 추출하여 정확히 조회할 수 있게 하세요.
한 장비가 선택되면 해당 ERP 1행과 정확한 같은 모델 SW만 보내고 전체 자료를 매번 보내지 마세요.
모델만 질문하면 그 모델의 근거 범위를 쓰되 장비 한 개를 임의로 선택하지 마세요.
로딩·중복 전송 방지·대화 기록·실제 최종 완료 소요 초·Task 상태를 표시하세요.
로컬 조회 안내와 실제 Agent 답변은 명확히 구분하세요. 조회 버튼으로 실제 Agent에 요청하세요.
package.json·lockfile·Dockerfile·추가 패키지는 수정하지 마세요.
```

## 재개 검증 기록

2026-10-21 21:42 KST, 단계 1 생성 후 미리보기에서 확인했다.

- ERP #1 조회: ERP 1행·BC380 SW 5행 연결, SW 등록일 내림차순.
- 후속 제조일: 같은 ERP #1의 2026-01-20 유지.
- ERP #2 조회: BC380PRO SW 4행으로 분리.
- ERP #4 조회: 버전 세 칸 모두 자료 없음, SW 최신값으로 대체하지 않음.
- 새 대화 후 후속 질문: 이전 장비가 없다는 안내, 이전 행 재사용 없음.
- 단계 2 실제 Agent 연결 생성·카드 연결 성공. 새 미리보기 출처를 기존 서버의 명시적 CORS 허용 목록에 반영했다. 전체 출처 허용으로 바꾸지 않았다.
- 새 앱 미리보기의 첫 통합 질문은 40.2초에 실제 Agent 답변을 표시했다. ERP #1 출고일 2026-02-25, AP C0.007과 최신 등록 AP C0.010을 구분했다. 이는 1회 브라우저 완료 시간이며 기존 앱 평균과 같은 표본이 아니다.
- 기존 Agent가 답변에 붙인 스냅샷 날짜는 이번 앱이 전달한 메타데이터로 확인되지 않았다. 답변 전체의 정확성 검증과 연결 성공을 구분한다.
- 같은 장비의 후속 제조일 질문은 6.0초에 완료, 2026-01-20과 ERP #1을 답했고 앞선 응답과 같은 contextId가 유지됐다.
- 웹 배포는 미리보기 검증과 별도이며 공개 접근 승인 화면까지 준비했다. 배포·외부 URL 시험 결과는 후속 기록 예정.
